# 온라인 업무 수첩

휴대폰 번호·비밀번호로 가입하고 사용자별 일정을 온라인 PostgreSQL에 저장하는 업무 수첩입니다. 이름 입력과 테스트용 가입 미리보기를 실제 가입·로그인 흐름으로 교체했습니다.

배포 주소: https://edu-apply-02.vercel.app/

**온라인 기능은 DB 테이블·Vercel 환경 변수 설정이 필요합니다.** [DB_SETUP.md](DB_SETUP.md)의 설정을 완료하고 새 코드를 배포한 뒤 연결을 확인하세요. 화면을 더블클릭하는 방식으로는 서버 API를 사용할 수 없습니다.

## 주요 기능

- 가입: 휴대폰 번호, 비밀번호, 비밀번호 확인. 비밀번호는 12~128자입니다.
- 로그인·로그아웃: 서버 쿠키 세션으로 인증합니다. 번호는 아이디이며 SMS 발송·소유자 확인은 하지 않습니다.
- 일정: 업무·개인 분류, 주간·월간 보기, 기간·분류 필터, 등록·변경·삭제
- D-day: 오늘부터 7일 후까지 전체 분류의 일정을 표시합니다. 업무는 초록색, 개인은 금색입니다.
- 시간 규칙: 07:00~23:00, 30분 단위. 같은 사용자의 같은 날짜에 겹치는 시간은 DB에서도 거부합니다.
- 기존 브라우저 일정: 로그인 후 가져오기 버튼을 눌러 현재 계정에 복사합니다. 원본은 삭제하지 않습니다.

로그인 전에는 일정 저장이 비활성화됩니다. DB 오류 시 브라우저 저장으로 대체하지 않고 오류를 알립니다. 다른 기기의 변경사항은 **DB 일정 다시 조회** 또는 새로고침으로 반영합니다. 사용자별 비공개 수첩이며 팀 공유 기능은 없습니다.

## 검증

브라우저에서 가입·로그인·등록을 직접 시험하려면 프로젝트 폴더에서 **`npm.cmd run dev`**를 실행하고 **http://127.0.0.1:3000**으로 접속하세요. 운영 DB와 분리된 로컬 DB를 자동 생성하며 Supabase 키가 필요하지 않습니다. 설치·저장·중지 방법은 [LOCAL_TEST.md](LOCAL_TEST.md)를 참고하세요.

Node.js 24 사용을 권장합니다. 운영 서버와 화면에는 외부 런타임 의존성이 없으며 SQL 검증용 개발 의존성만 설치합니다.

```powershell
npm ci
npm test
npm run build
```

`dist/`에는 화면 파일만 배포하고, 서버 코드·SQL·문서·환경 파일은 정적 공개하지 않습니다. Vercel은 `api/` 함수를 별도로 배포합니다. 빌드 설정은 [DB_SETUP.md](DB_SETUP.md)를 참고하세요.

모의 API 테스트와 로컬 SQL 검증은 실제 Supabase REST 연결·Vercel 보안 쿠키·모바일 화면 검증을 대체하지 않습니다. DB 설정 후 가입, 재로그인, 사용자별 분리, 두 기기 동시 수정, 가져오기와 로그아웃을 실제 HTTPS 주소에서 확인해야 합니다.

## 계정 운영 범위

보안 점검 결과와 개선 우선순위는 [SECURITY_REVIEW_2026-10-22.md](SECURITY_REVIEW_2026-10-22.md)에 정리했습니다. 읽기 전용 운영 DB 권한 점검은 [db/security_check.sql](db/security_check.sql), 운영 자료를 사용하지 않는 재현은 `node scripts/security-review.cjs`로 실행합니다.

전화번호 소유자를 확인하지 않으므로 다른 사람이 번호를 먼저 등록할 수 있습니다. 본인 번호를 사용하고, 자동 비밀번호 찾기·번호 변경·탈퇴 UI는 아직 제공하지 않습니다. 비밀번호를 분실하면 번호만으로 자동 재설정하지 않습니다. 계정 복구·탈퇴가 필요하면 운영자가 별도 본인 확인 후 DB와 세션 정리 절차를 수행해야 합니다. 유료 문자 인증은 사용하지 않습니다.
